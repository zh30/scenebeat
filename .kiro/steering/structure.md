## Where new code goes

- New transcript, template, duration, override, subtitle, storyboard, saved-work, or launch logic: a pure module in `src/core/`, with tests in `tests/`.
- New template: add it to `TEMPLATES` in `src/core/types.ts`, then update `assignTemplate.ts`, `deriveData.ts`, `validate.ts`, `sceneTheme.ts`, `sceneLayout.ts`, `SceneView.tsx`, `src/video/paintFrame.ts`, `templateLabels.ts`, and the styles.
- Layout or look of a scene: `sceneTheme.ts` and `sceneLayout.ts`, so the Player preview and the exported video stay identical.
- Playback behavior: `playbackReducer.ts` first; touch `usePlayback.ts` only for timing.
- Code that needs canvas, MediaRecorder, `requestAnimationFrame`, or document visibility for video: `src/video/`, with the API passed in as a dependency.
- Code that needs the service worker, install events, `localStorage`, `launchQueue`, `history`, or page visibility for PWA features: `src/pwa/`, injected through `PwaDeps`; only `browserDeps.ts` builds the real dependencies.
- Manifest changes: `src/pwa/manifest.ts` (keep every URL relative); icons and favicon: `scripts/generate-pwa-assets.ts`, then commit `public/`.
- UI: a component in `src/components/`, one component per file, receiving data via props from `App`.
- Node-only tooling: `scripts/`, never imported by `src/`.
- New property tests: next free `pNN` number (currently P66), matching a property in the design document of the spec that adds it.
